Client-Side Architecture

Browser Privacy & Case File Handling

Incident Reconstruction Studio runs directly inside your browser so sensitive scene photographs, diagrams, and case notes do not have to be uploaded to an external application server.

How Project Data Is Processed

When you upload a scene image in Step 1 or enter routes, markers, timelines, and evidence items, that data stays inside active browser page memory. Rendering the canvas, generating PNG downloads, formatting printable exhibits, and creating JSON or CSV files all execute locally on your device.

Handling Exported Project JSON Files

Because exported .json project files embed your uploaded scene image (as a Data URL) along with case notes and evidence metadata, treat every saved project file as confidential case material:

  • Store exported JSON, PNG, and CSV files only inside your organization's approved secure case management system or encrypted storage.
  • Close or refresh the browser tab on shared workstations after exporting, since refreshing clears active browser memory.
  • Verify you hold authorization to use any aerial imagery, floor plans, or photographs imported into the workspace.

Future Payment & Access Checkpoint Architecture

Export actions pass through a dedicated client-side gate module (assets/js/export-gate.js). When payment processing is connected, checkout authentication will handle licensing and payment tokens separately without requiring your confidential scene imagery to be transmitted to a storage backend.

Zero Server Uploads

Local-First Execution

No database account or remote file upload is required to build a scene exhibit in the Studio.
